## The idea in one paragraph

L54-L55 ran on a laptop. A company runs this on a shared data platform, where the data already lives,
jobs run on a schedule, and models sit in a governed catalogue. We move the churn model to **Databricks
Free Edition**:

1. port the features to Spark;
2. train there and log to **Databricks MLflow**;
3. register the model in **Unity Catalog** with a `@champion` alias;
4. add a **scoring task** to the existing `meridian_weekly` job (from L21).

The test of success: **the cloud version gives the same answers as the laptop version.**

## Key words

- **Databricks**: a cloud data platform. Data lives in tables, code runs in **notebooks**, and **jobs**
  run notebooks on a schedule.
- **Free Edition**: the no-cost version. It only offers **serverless** compute (you don't manage
  machines) and has some restrictions, one of which we hit.
- **Spark**: the engine Databricks uses for big tables. Like polars, but spread over many machines.
- **Unity Catalog (UC)**: Databricks' catalogue for tables *and* models, with names like
  `catalog.schema.name` (here `workspace.meridian.churn_model`).
- **Task / job**: a job is a chain of tasks. Each task waits for the ones it `depends_on`.
- **`%run`**: includes another notebook's code, like `import` for notebooks.

## How we kept laptop and cloud identical

The biggest risk when moving a model is that the features get computed **slightly differently**
(training-serving skew, L55). So:

1. **One feature notebook.** `05_churn_features` is a line-by-line Spark port of
   `make_features()`, and both training (06) and scoring (07) include it with `%run`. There's no second copy
   to drift apart.
2. **Asserts against the laptop.** The training notebook stops if the customer counts aren't exactly
   988,844 / 984,525, or if the AUC differs from the local 0.7965 by more than 0.002.
3. **Compare the outputs.** The table above shows scoring results side by side.

| polars (laptop) | Spark (Databricks) | Why it matters |
|---|---|---|
| `pl.col("sale_date").n_unique()` | `F.countDistinct("sale_date")` | visits = distinct shopping days |
| `.filter(...).n_unique()` | `F.countDistinct(F.when(..., col))` | `when` without `otherwise` gives null, and countDistinct skips nulls |
| `cutoff.replace(year=cutoff.year - 1)` | `F.add_months(c, -12)` | same 12-month window |
| `pl.col("age").median()` | `F.percentile("age", 0.5)` | exact median (not the approximate one) |
| `.round(9)` (L55 fix) | `F.round(col, 9)` | parallel sums differ in the last decimals |

## Two failures and their fixes

**1. `log_model() missing 1 required positional argument: 'artifact_path'`.** Databricks
serverless comes with an older MLflow (2.x), where the argument we used (`name=`) doesn't exist yet. Our
laptop has MLflow 3.18. Lesson: **the platform's package versions aren't yours.**

**2. `AccessDenied ... s3:PutObject ... explicit deny`.** Saving the model into Unity Catalog was
blocked. Free Edition doesn't allow older MLflow clients to write straight into the underlying cloud
storage. The fix:

```python
# MAGIC %pip install lightgbm==4.7.0 mlflow==3.18.0 -q
...
os.environ["MLFLOW_USE_DATABRICKS_SDK_MODEL_ARTIFACTS_REPO_FOR_UC"] = "true"
```

Pin the **same MLflow version as the laptop** and tell it to upload through the Databricks Files API
instead. Third attempt: success. The two failed attempts left model versions 1 and 2 stuck in
`PENDING_REGISTRATION`. They're harmless (the alias points to v3) but can be deleted.

Before the fix, the training notebook already got as far as the AUC check (that assert passed). That's why
we put cheap correctness checks **before** expensive or fragile steps: a failure later tells you
the earlier steps were fine.

```python

```
A **widget** is a notebook parameter. The job passes `cutoff` (`base_parameters`); if run by hand,
the default is used.

```python
if not all(checks.values()):
    raise RuntimeError(f"STOPPED: data checks failed for cutoff {CUTOFF} - nothing scored")
```
Same hard checks as L55. Raising an error makes the task, and the job, **fail** visibly (red in
the Jobs page), and nothing is written.

```python
model = mlflow.lightgbm.load_model(f"models:/{MODEL}@champion")
```
Always load whatever `@champion` points to. Promoting a new model never needs a code change.

```python
TABLE = "workspace.meridian.weekly_churn_audiences"
if spark.catalog.tableExists(TABLE):
    out.write.mode("overwrite").option("replaceWhere", f"cutoff = DATE'{CUTOFF}'").saveAsTable(TABLE)
else:
    out.write.saveAsTable(TABLE)
```
Each week's rows carry a `cutoff` column. `replaceWhere` overwrites **only that week's rows**, so
re-running a week is safe (no duplicates) and older weeks stay. This is called an **idempotent** write.

## What an interviewer might ask

**Q: How do you make sure a model behaves the same after moving platforms?**
A: One shared feature implementation (`%run` in both training and scoring), hard asserts on row
counts and AUC against the reference (988,844 / 984,525 customers; AUC 0.7964 vs 0.7965), and an
output comparison: same 994,320 customers, same PSI, audiences within 0.02%.

**Q: Why register the model in Unity Catalog instead of saving a file?**
A: Versioning, an alias (`@champion`) the job resolves at run time, lineage back to the MLflow run,
and permissions. Promoting or rolling back is moving the alias, not editing the job.

**Q: The model upload failed with AccessDenied. How did you debug it?**
A: The error showed a direct S3 write being explicitly denied, and the earlier error showed the platform's
MLflow was 2.x. Free Edition restricts direct storage writes, so I pinned the same MLflow version as
locally (3.18) and switched uploads to the Databricks Files API. Lesson: pin your dependencies in the
notebook; the platform's defaults change.

**Q: Why does the scoring task write with replaceWhere?**
A: Idempotency. If a run is retried or re-run for the same week, it replaces that week's rows instead of
duplicating them, while keeping the history of other weeks for monitoring.

**Q: How did you handle credentials?**
A: The CLI uses a browser (OAuth) login stored in `~/.databrickscfg` on the laptop. No token is in
the repo or in any notebook; I scanned the repo for token patterns before committing.
