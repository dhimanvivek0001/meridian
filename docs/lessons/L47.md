# Lesson 47: "Looks like what you bought" - visual candidates (closes M9)

Script: `scripts/vision_candidates.py` (about 5 minutes to run)
Module: M9 Computer vision (lesson 2 of 2)

## The idea in one paragraph

Lesson 45 found that our recommender is capped by **candidate recall**: only 23.96% of
test-week buyers bought anything in their candidate list. Lesson 46 turned product photos into
CLIP embeddings. Here we add a fourth candidate source: for each item a customer bought
recently, suggest the **5 photos that look most like it**. Then we ask two questions:
1. Does recall rise above 23.96%?
2. Is that better than simply adding the same number of extra bestsellers? This is the
   **fair control**.

## Important: we used a subset

Only **1,935 photos** are available (Kaggle rate limits stopped the download; see L46), roughly
the top ~1,940 sellers before the cut. An own item without a photo produces no visual
neighbours, and neighbours can only come from these 1,935 items. With all 105k photos the
source would be bigger, but probably no more precise. See "The honest verdict".

## The result first

| Candidate set (test week, 68,984 buyers) | Candidates per buyer | Recall (ceiling) |
|---|---:|---:|
| L45 sources (own + partners + top-50 bestsellers) | 59.6 | 23.96% |
| **+ visually similar items** | 64.8 | **24.55%** |
| Control: + 5 more bestsellers instead | 64.6 | **24.75%** |

| Ranker | Hit rate (12 items) |
|---|---:|
| L45 ranker | 11.52% |
| L47 ranker with visual source + features | 11.43% (-0.09 pts) |

**Answer to your question: yes, recall goes above 23.96% (to 24.55%).** But 5 extra
bestsellers do slightly better, and the final hit rate doesn't improve.

## Key words

- **Candidate recall**: share of buyers who bought at least one item in their candidate list.
  It's the ceiling for any ranker.
- **Control**: a comparison that changes only the thing you are *not* testing. More candidates
  almost always raise recall, so we compare against "the same number of extra candidates,
  chosen the boring way".
- **Precision of a source**: of the candidates it adds, what share actually get bought.

### Step 1: the visual neighbour table

```python
e = pl.read_parquet("data/clean/image_embeddings.parquet")
ids, emb = e["article_id"].to_list(), e["emb"].to_numpy()
sim = emb @ emb.T
np.fill_diagonal(sim, -1)
nn = np.argsort(-sim, axis=1)[:, :N_VIS]
```
Exactly the L46 trick: cosine similarity of every photo to every photo, hide self-similarity,
take the top 5 per row.

```python
vis = pl.DataFrame({
    "article_id": np.repeat(ids, N_VIS),
    "article_id_v": np.array(ids)[nn.ravel()],
    "sim": sim[np.arange(len(ids))[:, None], nn].ravel(),
})
assert vis.height == len(ids) * N_VIS
```
Turn the 1,935 x 5 neighbour grid into a long table, one row per (item, neighbour):
- `np.repeat(ids, 5)`: each item ID written 5 times (A, A, A, A, A, B, B, ...).
- `nn.ravel()`: the grid flattened into one long list of neighbour positions, which become IDs.
- `sim[np.arange(...)[:, None], nn]`: "fancy indexing" that picks each row's 5 similarity scores.

Before (grid, one row) and after (long table):

| item | neighbour 1 | neighbour 2 | ... |
|---|---|---|---|
| Cindy cropped LS | Apollo Seamless Cropped LS | Lion top | ... |

| article_id | article_id_v | sim |
|---|---|---:|
| Cindy cropped LS | Apollo Seamless Cropped LS | 0.98 |
| Cindy cropped LS | Lion top | 0.98 |

Output: 1,935 x 5 = **9,675 rows, median similarity 0.96**. The scores are high because the studio
photos look alike, as L46 noted.

## Why didn't it help? (the honest verdict)

1. **People rarely buy a near-twin of what they just bought.** If you bought a black cropped
   top last week, the most similar photo is another black cropped top, which you probably don't
   need. Basket partners (L44) capture "goes with", which is more useful than "looks like".
2. **Bestsellers are a strong, cheap source.** Five extra bestsellers beat five look-alikes,
   because popularity during a given week is very predictive.
3. **The subset limits reach.** Neighbours come only from the top ~1,940 sellers, and only
   own items with a photo can seed them. More photos would add more candidates, but the
   0.23% precision suggests they would mostly be more misses.
4. **Where image embeddings *do* shine:** brand-new items with no sales yet (cold start), a
   "similar items" panel on a product page, visual search, and catalogue tagging. That's a
   different job from predicting next week's purchase.

This is a useful negative result: we measured a fair control, so we know the gain in recall
came from *adding candidates*, not from the photos specifically.

## What an interviewer might ask

**Q: Recall went up. Why don't you call it a win?**
A: Adding any candidates raises recall. The fair test is against the same number of
extra candidates from a simple source. Five more bestsellers raised recall more (24.75% vs
24.55%), and the end-to-end hit rate didn't improve (11.43% vs 11.52%).

**Q: What is precision per source, and why look at it?**
A: Of the candidates a source adds, the share that get bought. Visual-only candidates: 0.23%
vs 0.55% overall. It tells you whether a source adds signal or mostly noise for the ranker to
filter out.

**Q: How would you use image embeddings productively here?**
A: For cold-start items (no purchase history, so popularity and pairs can't score them),
as a ranker feature like "similarity to the customer's taste profile" (the average of their item
embeddings) rather than as a raw source, and for search and "similar items" widgets.

**Q: Any leakage risk in this setup?**
A: The test is clean: the photo set was chosen from sales before 16 Sep, and all features
use data before each cut. One subtle point: the photo set was chosen using sales up to 15 Sep, which overlaps the
*training* label weeks (2-15 Sep), so training saw a slightly "lucky" pool. That can only
help the visual model, and it still didn't win, so the conclusion stands.

**Q: Only 1,935 of 3,000 photos. Does that invalidate the result?**
A: It limits it. The conclusion is about the top sellers, which are the items customers
mostly own and buy. I'd re-check with the full photo set before rejecting the idea
for good, but the low precision (0.23%) says the main issue is the signal, not coverage.
